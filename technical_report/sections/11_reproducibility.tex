\chapter{Reproducibility, Verification, and Software Environment}
\label{ch:reproducibility}

\section{Reproducibility strategy}

Reproducibility is implemented through versioned directories, frozen protocols,
deterministic seeds, source fingerprints, explicit sample IDs, saved split
memberships, persisted bases and complete classifier pipelines, fold-level JSON
predictions, and separate replay verification. Earlier experiments are retained
even when corrected later.

\section{Recorded software environment}

The V2 artifact manifest records Python 3.10.11, NumPy 2.2.6, SciPy 1.15.3,
scikit-learn 1.7.2, Joblib 1.6.0, TensorLy 0.9.0, and threadpoolctl 3.6.0. V4 adds
\code{xgboost-cpu} 3.2.0. MiKTeX 25.12 is used only to compile this report; it is
not part of the modeling environment.

\section{Recommended execution order}

The versioned scripts should be run in dependency order from the workspace root:

\begin{enumerate}
  \item \code{py -3.10 preprocessing/build\_balanced\_dataset.py}
  \item \code{py -3.10 preprocessing/audit\_primary\_signal\_quality.py}
  \item \code{py -3.10 preprocessing/build\_clean\_primary\_dataset.py}
  \item \code{py -3.10 tensor\_pipeline/tensorize\_subjects.py} and the V1
  rank benchmarks if historical reproduction is required;
  \item \code{py -3.10 tensor\_pipeline/v2/prepare.py}, then V2 tests,
  benchmark, verification, and reporting;
  \item \code{py -3.10 tensor\_pipeline/v3\_waveform/prepare.py}, then V3
  tests, run, convergence sensitivity, verification, and finalization; and
  \item \code{py -3.10 tensor\_pipeline/v4\_tuning/test\_tuning.py}, then V4
  benchmark and verification/report scripts.
\end{enumerate}

Exact reproduction guidance and stage-specific caveats remain in the versioned
README and protocol files. The code deliberately refuses to overwrite some
existing V3 outputs; this protects completed experiments from accidental
replacement.

\section{Why a booster file is not the whole model}

An exported XGBoost booster receives already prepared features. The clinically
meaningful pipeline also includes the training-derived TT/Tucker basis when
applicable, feature selection, standardization, class ordering, and subject-level
pooling. A booster must therefore be paired with its corresponding complete
pipeline and basis provenance. Joblib artifacts should be loaded only from a
trusted local source because deserialization can execute code.
